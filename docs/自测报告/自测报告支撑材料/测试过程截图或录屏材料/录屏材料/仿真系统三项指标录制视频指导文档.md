# 仿真系统三项指标录制视频指导文档

## 一、录制目标

本视频只需要证明 3 个指标：

1. 至少完成 1 种极端灾害条件下的数据仿真；
2. 仿真系统中至少实现专用设备接入功能；
3. 支持不少于 1200 个用户节点接入。

推荐录制场景：`台风灾后残余网络 + PPO（基线）`。  
原因：台风场景用户数为 `1500`，一次演示即可同时覆盖“极端灾害仿真”和“不少于 1200 用户节点”。

## 二、录制前提

前端已打开系统页面，后端已启动。

如果“策略测试”页里当前组合显示“缺少权重”，先到“模型训练”页训练一次对应组合，直到策略测试组合弹窗中显示“已匹配权重”后再录制。

## 三、录制步骤

| 步骤 | 前端操作 | 前端响应 | 验证指标 |
| --- | --- | --- | --- |
| 1 | 点击顶部菜单“策略测试” | 进入策略测试页，页面显示场景/算法组合区、“开始测试”按钮、设备接入模块、实时输出终端和场景图 | 进入仿真测试主流程 |
| 2 | 点击场景与算法组合区域 | 弹出“选择场景与算法”窗口，列表中显示场景、算法、状态 | 证明系统支持场景与算法组合选择 |
| 3 | 选择“台风灾后残余网络 + PPO（基线）”，要求状态为“已匹配权重” | 终端输出“已切换到台风灾后残余网络 + PPO（基线）” | 验证选择了 1 种极端灾害场景 |
| 4 | 等待场景自动同步 | 终端输出类似“已同步场景：台风灾后残余网络，用户 1500，残余基站 ... 个” | 验证指标 1：完成极端灾害场景导入；验证指标 3：用户节点数 1500，大于 1200 |
| 5 | 在“设备接入模块”点击“+ 添加设备” | 设备接入模块新增一行设备，显示接入设备、通信方式、关键参数、数量、x、y、状态、操作 | 验证指标 2：前端具备专用设备接入入口 |
| 6 | 将数量设为 `1`，x 设为 `0`，y 设为 `0` | 设备行中的数量和坐标显示为对应值 | 验证指标 2：专用设备参数可配置 |
| 7 | 点击“应用到当前测试” | 终端输出“已应用当前测试场景设备接入配置：...”，随后重新同步场景，日志显示“残余基站 1 个”或大于 0 | 验证指标 2：接入设备已进入当前仿真场景 |
| 8 | 点击“开始测试” | 按钮变为“测试中...”，终端输出“准备启动...”“当前场景已应用设备...”“加载模型...”“测试开始...”等过程日志 | 验证指标 1：灾害场景数据仿真开始执行 |
| 9 | 等待测试完成 | 终端输出“测试完成：平均奖励...，平均覆盖率...%”；按钮变为“重新测试”或状态显示完成 | 验证指标 1：极端灾害条件下仿真完成 |
| 10 | 查看测试结果区 | 结果区显示平均奖励、平均覆盖率、终态覆盖、终态广播、剩余预算、受灾场景文件、部署后场景文件 | 验证指标 1：仿真结果可见、可导出；验证指标 2：设备接入参与测试闭环 |

## 四、录屏中必须停留的关键画面

| 关键画面 | 说明 |
| --- | --- |
| “台风灾后残余网络 + PPO（基线）” | 证明选择了极端灾害场景 |
| 终端日志“用户 1500” | 证明用户节点数不少于 1200 |
| “+ 添加设备”按钮和新增设备行 | 证明系统有专用设备接入功能 |
| 终端日志“已应用当前测试场景设备接入配置” | 证明设备配置已提交 |
| 终端日志“残余基站 1 个”或大于 0 | 证明设备进入仿真场景 |
| 点击“开始测试”后的流式日志 | 证明仿真不是静态展示，而是真实执行 |
| “测试完成：平均奖励...平均覆盖率...” | 证明仿真完成 |
| 结果区的平均奖励、平均覆盖率、导出路径 | 证明结果可查看、可留痕 |

## 五、三个指标如何对应

| 指标 | 视频中对应的操作与响应 |
| --- | --- |
| 至少完成 1 种极端灾害条件下的数据仿真 | 选择“台风灾后残余网络 + PPO（基线）”，点击“开始测试”，终端输出测试过程和“测试完成”，结果区显示平均奖励、覆盖率等指标 |
| 仿真系统中至少实现专用设备接入功能 | 点击“+ 添加设备”，配置数量和 x/y 坐标，点击“应用到当前测试”，终端显示设备配置已应用且残余基站数量大于 0 |
| 支持不少于 1200 个用户节点接入 | 选择台风场景后，终端同步日志显示“用户 1500”；也可选择洪水场景 1280 或地震场景 1360 |
