**【系统英文全称：RescueNet Reinforcement Learning System】**

**【系统英文简称：RescueNet-RL】**

# 一、文档目标

本文档面向前端重构开发人员。前端人员应根据原型界面重新实现真实前端页面，并把页面中的按钮、表单、图表和结果区接到当前后端接口。

本文只描述三件事：

- 每个菜单页面应该有什么布局。
- 用户点击哪个按钮时调用哪个接口。
- 接口传什么参数、返回什么字段、返回结果显示到页面哪里。

当前后端统一使用 `/api` 前缀，默认未接入正式登录认证、训练取消、设备入库、场景上传入库接口。文档中没有写的接口不要在前端虚构。

## 1.1 菜单与路由

| 菜单 | 路由 | 原型参考 | 当前后端接入 |
| :-- | :-- | :-- | :-- |
| 登录 | `#/login` | `登录.html` | 无后端接口 |
| 首页 | `#/home` | `首页.html` | 无后端接口，只做过程演示和跳转 |

## 1.2 全局接口约定

- API 基础地址：`/api`。
- 普通接口使用 JSON 请求和 JSON 响应。
- 训练过程、策略测试过程、链路仿真过程使用 `text/event-stream`。
- 坐标字段 `x` 表示区域网格行号，`y` 表示区域网格列号。
- `custom_base_stations = null` 表示使用场景默认残余网络。
- `custom_base_stations = []` 表示显式指定无残余基站。
- `custom_base_stations = [{...}]` 表示前端完全覆盖残余基站配置。

## 2.2 首页

首页只做灾后通信恢复过程演示和页面跳转，当前不调用任何后端接口。

### 页面布局

参考 `首页.html` 实现：

- 顶部菜单。
- 主视觉灾情/组网动画区域：展示用户节点、候选站点、基站、链路和指标面板的动态变化。
- 右上操作入口区域：保留“进入模型训练”入口。
- 五步流程展示区：按“灾情接入、候选站点、策略训练、组网回放、链路评估”顺序高亮当前步骤。
- 图例区域：说明断联用户节点、正常用户节点、候选站点、已部署基站、通信链路等视觉含义。
- 动画说明文案区：跟随当前步骤切换标题、说明和关键结果，不能只显示步骤名称。

### 首页动画显示要求

首页动画是一个完整的灾后通信恢复过程演示。前端应按 5 个阶段循环播放，也可以允许用户点击步骤手动切换。每个阶段都要同时更新 4 类内容：

- 步骤条：当前步骤高亮，已完成步骤显示完成态，未开始步骤显示等待态。
- 主视觉图：节点、站点、基站、链路或指标随阶段变化。
- 说明文案：显示当前阶段在做什么，不要只写“部署点位生成”“推荐序列收敛”这类短标签。
- 关键数字：展示演示用的节点数、站点数、轮次、覆盖率、吞吐等静态模拟值；这些值不是后端返回。

### 五步动画内容

| 步骤 | 主视觉应显示 | 说明文案应表达 | 关键数字示例 | 后端接口 |
| :-- | :-- | :-- | :-- | :-- |
| 灾情接入 | 地图上先出现用户节点，再将部分节点切换为断联/受灾状态；残余基站可显示为少量可用节点 | 接入灾害场景，识别受灾用户节点、断联用户节点和正常用户节点，形成后续恢复计算的初始态 | 受灾用户、断联用户、残余基站 | 无 |
| 候选站点 | 在地图上叠加候选站点点位，并用不同图标或颜色标识可部署基站类型 | 根据灾害场景和候选点位决定可部署的基站资源，例如宏站、背负式基站、中继站等，为策略训练提供动作空间 | 候选站点数、可用基站类型数 | 无 |
| 策略训练 | 候选站点被多轮次试探性点亮，覆盖范围逐轮扩大；曲线或进度条显示训练轮次变化 | 策略在候选站点上进行多轮部署模拟，比较覆盖、成本和广播效果，逐步学习更优的基站部署顺序 | 训练轮次、模拟部署次数、覆盖率提升 | 无 |
| 组网回放 | 清空训练试探态，按最终策略重新部署一遍基站；用户节点逐步由断联变为恢复，链路逐步连通 | 相当于执行一次策略测试：使用训练后的策略重新部署基站，并回放一次从灾情初始态到网络恢复态的过程 | 部署基站数、恢复用户数、活动链路数 | 无 |
| 链路评估 | 地图稳定在部署后状态，旁侧或下方显示指标卡片、雷达图、折线图或柱状图 | 对生成的组网方案输出覆盖率、广播覆盖、吞吐、丢包率、链路利用率等指标，用于判断方案质量 | 覆盖率、广播覆盖、吞吐、丢包率、链路利用率 | 无 |

### 动画文案建议

前端可直接使用以下文案作为首页步骤说明：

| 步骤 | 标题 | 说明 |
| :-- | :-- | :-- |
| 灾情接入 | 灾情接入，识别受灾用户节点 | 接入灾害场景后，系统在地图上标记正常用户、断联用户和残余可用基站，形成恢复计算的初始状态。 |
| 候选站点 | 候选站点，确定可部署基站资源 | 根据场景中的候选站点和设备能力，确定可部署的宏站、背负式基站、中继节点等资源范围。 |
| 策略训练 | 策略训练，多轮模拟基站部署 | 策略在候选站点上反复模拟部署，比较覆盖率、广播覆盖和资源成本，逐轮收敛推荐部署顺序。 |
| 组网回放 | 组网回放，重新执行一次部署测试 | 使用训练后的策略从灾情初始态重新部署基站，回放用户恢复连接、链路重构和覆盖扩展过程。 |
| 链路评估 | 链路评估，输出组网方案指标 | 对部署后的组网方案进行指标评估，展示覆盖率、广播覆盖、吞吐、丢包率和链路利用率等结果。 |

### 动画状态与图例

| 元素 | 建议视觉状态 | 含义 |
| :-- | :-- | :-- |
| 正常用户节点 | 蓝色或绿色小点 | 未受灾影响或已恢复连接的用户 |
| 断联用户节点 | 红色或灰色小点 | 灾情接入后无法接入网络的用户 |
| 候选站点 | 空心圆、十字标记或浅色点位 | 可部署基站的位置 |
| 已部署基站 | 基站图标或高亮站点 | 策略选择并部署的站点 |
| 通信链路 | 连线或流动线 | 用户与基站、基站与基站之间的通信连接 |
| 覆盖范围 | 半透明圆或热力区域 | 基站部署后覆盖的用户范围 |
| 指标卡片 | 数字卡片或小图表 | 当前组网方案评估结果 |

### 动画播放规则

- 默认自动循环播放，其中“灾情接入、候选站点、组网回放、链路评估”每步停留 2 到 4 秒。
- “策略训练”步骤建议停留约 10 秒，用于表现多轮次候选站点试探部署、覆盖范围扩展、训练曲线变化和推荐部署序列收敛。
- 用户点击步骤条时，应立即切换到对应步骤，并暂停或重置自动播放计时。
- 切换步骤时，只更新前端静态演示状态，不请求后端接口。
- 数字指标可以使用静态演示数据，但必须避免写成真实接口结果。
- 首页动画不要出现“正在请求”“训练任务已启动”“测试中”等会让用户误以为后端任务已执行的状态文案。

### 用户动作

| 用户动作 | 前端处理 | 后端接口 | 显示结果 |
| :-- | :-- | :-- | :-- |
| 进入首页 | 播放或展示五步过程 | 无 | 首页动画和流程说明 |
| 点击“进入模型训练” | 跳转 `#/train` | 无 | 进入模型训练页 |

首页当前不调用以下接口：`GET /api/scenarios`、`GET /api/train/latest-artifact`、`GET /api/train/artifacts`、`GET /api/ns3/status`、`GET /api/mahimahi/status`、`GET /api/mahimahi/traces`、`POST /api/simulate/scene`。

## 2.3 模型训练页

模型训练页用于确认训练场景、选择算法、配置参数、启动训练并展示训练过程。

### 页面布局

参考 `模型训练.html` 重构以下区域：

| 区域 | 页面内容 | 数据来源 |
| :-- | :-- | :-- |
| 场景信息区 | 灾害类型、场景名称、区域名称、网格规模、用户数量、重点区域、候选站点数量 | `GET /api/scenarios` |
| 设备与站点区 | 残余基站、候选站点、可用基站类型、支持通信模式 | `GET /api/scenarios` |
| 算法选择区 | PPO、DQN、A3C、MPPO 卡片或单选按钮 | 前端固定枚举 |
| 参数配置区 | 训练步数、奖励模式、学习率、折扣因子、batch size、rollout 步数、熵系数、clip range、评估间隔 | 场景接口 + 前端默认值 |
| 训练监控区 | 运行状态、run_id、日志终端、奖励曲线、覆盖率实时折线图、广播覆盖率实时折线图 | `POST /api/train` + `GET /api/train/{run_id}/stream` |
| 训练记录区 | 历史训练列表和训练详情 | `GET /api/train/artifacts`、`GET /api/train/artifacts/detail` |

训练监控区应位于参数配置区下方、训练记录区上方。点击“开始训练”并拿到 `run_id` 后，页面应自动滚动或聚焦到训练监控区，使用户能立即看到运行状态、日志和实时曲线。

训练监控区内部建议按以下方式组织：

| 子区域 | 显示内容 | 数据来源 |
| :-- | :-- | :-- |
| 状态栏 | `run_id`、训练状态、当前 step、当前 episode | `POST /api/train` 响应和训练事件流 |
| 实时指标卡片 | 最新奖励、最新覆盖率、最新广播覆盖率、最佳覆盖率、最佳广播覆盖率 | 训练事件流 |
| 实时曲线区 | 奖励曲线、覆盖率曲线、广播覆盖率曲线；覆盖率和广播覆盖率也可以放在同一张双折线图中 | 训练事件流 |
| 终端日志区 | status、episode、update、evaluation、completed、error 事件转成的日志 | 训练事件流 |

实时覆盖率和广播覆盖率不是后端图片接口。前端需要消费训练事件流中的数值字段，用 ECharts、Chart.js 或项目选定的图表库实时绘制折线图。训练完成后后端会生成 `training_coverage_curve.png` 作为训练产物文件；该文件可在训练记录详情中展示路径或作为后续静态文件能力扩展，不作为实时曲线的数据源。

### 页面初始化

进入模型训练页后立即调用：

```http
GET /api/scenarios
```

请求参数：无。

返回关键字段：

| 字段 | 说明 | 页面显示位置 |
| :-- | :-- | :-- |
| `scenarios[].name` | 场景标识 | 场景下拉框、启动训练入参 |
| `scenarios[].disaster_type` | 灾害类型 | 灾害类型选择器 |
| `scenarios[].region_grid.name` | 区域名称 | 场景信息区 |
| `scenarios[].region_grid.rows`、`cols` | 网格行列数 | 网格规模 |
| `scenarios[].region_grid.geo_bounds` | 经纬度边界 | 覆盖范围 |
| `scenarios[].region_grid.cell_labels` | 重点区域标签 | 重点区域列表 |
| `scenarios[].num_users` | 用户数量 | 受灾用户规模 |
| `scenarios[].candidate_sites` | 候选站点数量 | 候选站点统计 |
| `scenarios[].candidate_site_preview` | 候选站点预览 | 候选站点表格或地图点位 |
| `scenarios[].base_stations` | 可用基站类型 | 设备与站点区 |
| `scenarios[].reward_profiles` | 奖励模式列表 | 奖励模式下拉框 |
| `scenarios[].default_reward_profile` | 默认奖励模式 | 参数默认值 |

`reward_profiles[]` 元素包含 `key`、`label`、`description`、`coverage_weight`、`bandwidth_weight`、`throughput_weight`、`broadcast_weight`、`device_cost_weight`、`bandwidth_cost_weight`。`base_stations[]` 元素包含 `name`、`label`、`max_throughput`、`max_users`、`device_cost`、`bandwidth_cost`、`supported_modes`。`candidate_site_preview[]` 元素包含 `site_index`、`x`、`y`、`region_label`、`category`、`lat_lon_bounds`。

页面初始化显示：

- 默认选中第一条场景或后端返回的默认场景。
- 灾害类型、区域、用户数量、候选站点数量、可用基站类型同步刷新。
- 默认算法选中 `ppo`。
- 奖励模式选中场景的 `default_reward_profile`。

### 用户动作与接口

| 用户动作 | 前端处理 | 后端接口 | 显示结果 |
| :-- | :-- | :-- | :-- |
| 切换场景 | 从已加载的 `scenarios` 中切换当前场景 | 无 | 刷新场景信息、设备、奖励模式 |
| 选择算法 | 更新当前算法 | 无 | 高亮当前算法卡片 |
| 修改训练参数 | 更新表单状态 | 无 | 参数表单显示新值 |
| 点击“开始训练” | 校验场景、算法、参数后创建训练任务 | `POST /api/train` | 显示 run_id，状态变为训练中 |
| 训练创建成功 | 根据返回的 `run_id` 订阅训练事件 | `GET /api/train/{run_id}/stream` | 日志和曲线实时追加 |
| 点击“停止训练” | 只停止前端事件流监听 | 无 | 状态显示“已停止监听”；后端训练不取消 |
| 点击“训练记录” | 查询历史训练产物 | `GET /api/train/artifacts` | 显示训练记录表 |
| 点击训练记录“查看” | 查询单次训练详情 | `GET /api/train/artifacts/detail?run_dir=...` | 显示训练配置、指标和产物路径 |

### 开始训练接口

```http
POST /api/train
Content-Type: application/json
```

请求体：

| 字段 | 类型 | 必填 | 来源 | 说明 |
| :-- | :-- | :--: | :-- | :-- |
| `scenario_name` | string | 是 | 当前场景 `name` | 场景标识 |
| `env_type` | string | 否 | 固定 `multimodal` | 环境类型 |
| `algorithm` | string | 否 | 算法选择区 | `ppo`、`dqn`、`a3c`、`mppo` |
| `total_timesteps` | integer/null | 否 | 参数表单 | 训练总步数，最小 1000 |
| `stochastic_eval` | boolean | 否 | 参数表单 | 评估是否随机采样 |
| `reward_mode` | string/null | 否 | 奖励模式下拉框 | 来自 `reward_profiles[].key` |
| `learning_rate` | number/null | 否 | 参数表单 | 学习率，必须大于 0 |
| `discount_factor` | number/null | 否 | 参数表单 | 折扣因子，范围 `(0, 1]` |
| `batch_size` | integer/null | 否 | 参数表单 | batch size，最小 1 |
| `rollout_steps` | integer/null | 否 | 参数表单 | rollout 步数，最小 1 |
| `entropy_coef` | number/null | 否 | 参数表单 | 熵系数，最小 0 |
| `clip_range` | number/null | 否 | 参数表单 | PPO clip range，必须大于 0 |
| `eval_interval` | integer/null | 否 | 参数表单 | 评估间隔，最小 1 |

请求示例：

```json
{
  "scenario_name": "typhoon_residual",
  "env_type": "multimodal",
  "algorithm": "ppo",
  "total_timesteps": 12000,
  "stochastic_eval": true,
  "reward_mode": "coverage_balance",
  "learning_rate": 0.0003,
  "discount_factor": 0.99,
  "batch_size": 256,
  "rollout_steps": 1024,
  "entropy_coef": 0.01,
  "clip_range": 0.2,
  "eval_interval": 4
}
```

响应：

```json
{
  "run_id": "4e871205b50c4a4ca617346ca260e7ce"
}
```

页面显示：

- 在训练监控区显示 `run_id`。
- “开始训练”按钮切换为“停止展示”或“停止监听”。
- 训练状态显示“初始化中/训练中”。
- 清空上一轮日志和曲线，准备接收事件流。

### 训练事件流

```http
GET /api/train/{run_id}/stream
Accept: text/event-stream
```

每条消息为 `data: {json}`。除最终 `end` 消息外，训练事件统一包含 `type`、`payload`、`timestamp` 三个顶层字段。

| 事件类型 | 返回字段 | 页面显示 |
| :-- | :-- | :-- |
| `status` | `payload.state`、`payload.step` | 状态标签、当前 step |
| `episode` | `payload.episode`、`payload.reward`、`payload.coverage`、`payload.broadcast`、`payload.steps`、`payload.reason` | 日志追加；曲线追加单回合点 |
| `update` | `payload.update`、`payload.step`、`payload.mean_reward`、`payload.mean_coverage`、`payload.mean_broadcast`、`payload.loss_pi`、`payload.loss_v` | 日志追加；曲线追加均值点 |
| `evaluation` | `payload.step`、`payload.avg_reward`、`payload.avg_coverage`、`payload.avg_broadcast` | 阶段评估卡片和曲线 |
| `completed` | `payload.step`、`payload.episodes`、`payload.total_timesteps` | 训练器完成事件 |
| `error` | `payload.message` | 错误提示 |
| `end` | `status` | 关闭事件流显示 |

实时图表字段对应关系：

| 图表 | X 轴 | Y 轴字段 | 说明 |
| :-- | :-- | :-- | :-- |
| 奖励曲线 | `payload.episode` 或 `payload.step` | `payload.reward`、`payload.mean_reward`、`payload.avg_reward` | episode、update、evaluation 事件可分别显示为单回合、训练均值、评估均值 |
| 覆盖率曲线 | `payload.episode` 或 `payload.step` | `payload.coverage`、`payload.mean_coverage`、`payload.avg_coverage` | 实时展示用户恢复覆盖率变化 |
| 广播覆盖率曲线 | `payload.episode` 或 `payload.step` | `payload.broadcast`、`payload.mean_broadcast`、`payload.avg_broadcast` | 实时展示广播服务覆盖率变化 |

前端可以优先使用 `episode` 事件画单回合曲线，用 `evaluation` 事件叠加评估点；如果训练事件过密，则使用 `update` 或 `evaluation` 事件作为主曲线，避免图表刷新过快。

| 字段 | 类型 | 来源 | 说明 |
| :-- | :-- | :-- | :-- |
| `trace_name` | string | Trace 下拉框 | 不带 `.trace` 后缀 |
| `duration_s` | number | 时长输入 | 1 到 300 秒 |
| `rtt_ms` | number | RTT 输入 | 1 到 2000 ms |
| `buffer_packets` | number | buffer 输入 | 1 到 10000 |
| `window_ms` | number | 窗口输入 | 100 到 5000 ms |


| `result` | `payload.stats` | 统计指标区 |
| `error` | `payload.message` | 错误提示 |
| `end` | `payload.state` | 结束状态 |

| 字段 | 显示 |
| :-- | :-- |

## 2.7 设备管理页

设备管理页用于按灾害场景展示和配置该场景可用的基站设备类型及能力参数。页面必须先选择灾害场景，再展示该场景下的设备类型和参数配置表。

当前后端只提供设备资料查询，没有正式设备新增、修改、删除、保存接口。因此“配置参数”是前端本地配置：用于页面预览、临时方案编辑或导出草稿，不会写回后端，也不会自动影响训练和策略测试接口。

### 设备参数配置

用户在灾害场景选择区选中场景后，前端应把该场景的 `base_stations` 复制到本地可编辑状态。设备参数配置区必须支持以下字段：

| 参数 | 控件 | 初始值来源 | 说明 |
| :-- | :-- | :-- | :-- |
| 设备 key | 只读文本 | `base_stations[].name` | 后端识别设备类型的 key，不建议编辑 |
| 设备显示名称 | 文本输入 | `base_stations[].label` | 页面显示名称 |
| 峰值吞吐 | 数字输入 | `base_stations[].max_throughput` | Mbps |
| 最大接入用户 | 数字输入 | `base_stations[].max_users` | 用户数量 |
| 设备成本 | 数字输入 | `base_stations[].device_cost` | 资源成本权重 |
| 带宽成本 | 数字输入 | `base_stations[].bandwidth_cost` | 带宽成本权重 |
| 支持模式 | 多选标签或可编辑标签列表 | `base_stations[].supported_modes` | 通信模式数组 |

参数配置交互规则：

- 切换灾害场景时，先询问是否丢弃当前未应用的本地修改；确认后加载新场景的设备参数。
- 点击某个设备卡片时，右侧或下方参数配置区显示该设备的完整参数。
- 修改参数后，参数清单区和设备卡片摘要应立即反映本地修改。
- 点击“重置为场景默认值”时，从最近一次 `GET /api/scenarios` 返回值恢复当前场景的设备参数。
- 点击“应用本地配置”时，只更新当前页面本地状态，不调用后端。
- 点击“导出配置 JSON”时，导出当前选中场景和本地设备参数，供后续人工归档或后端扩展使用。

导出 JSON 建议结构：

```json
{
  "scenario_name": "flood_no_residual",
  "disaster_type": "flood",
  "base_stations": [
    {
      "name": "mesh_uav",
      "label": "Mesh UAV",
      "max_throughput": 70.0,
      "max_users": 60,
      "device_cost": 0.75,
      "bandwidth_cost": 0.02,
      "supported_modes": ["Mesh_UAV"]
    }
  ]
}
```

- 不要把“应用本地配置”或“导出配置 JSON”描述为后端入库。

- 如果要让设备管理页的参数真正影响训练或策略测试，需要后端新增设备参数保存接口，或扩展训练/仿真请求体支持设备参数覆盖。

# 四、开发约束

- 首页当前不调用后端接口。
- 页面说明和实现都必须明确“哪个按钮触发哪个接口”。
- 不要把接口简单堆在页面底部。
- 不要虚构登录、训练取消、设备入库、场景上传接口。
- 所有场景名、奖励模式、基站类型必须来自 `GET /api/scenarios`。
- SSE 页面必须处理 `error` 和 `end` 事件。
- 训练页的“停止训练”只能停止前端监听，不能描述成取消后端训练。
- 设备管理页当前只能展示后端场景内基站资料；设备参数配置、应用和导出都不是后端入库。
