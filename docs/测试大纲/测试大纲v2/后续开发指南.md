# 测试大纲 v2 后续开发指南

## 1. 文档目的

本文档用于承接 [测试大纲v2.md](/mnt/data0/root/Projects/RescueNet-RL/测试大纲/测试大纲v2/测试大纲v2.md) 中识别出的所有缺口，明确：

- 当前哪些指标无法直观测试
- 当前缺的是前端入口、后端逻辑、数据样本还是结果展示
- 应先补什么，再测什么

## 3. 按指标分类的缺口分析

### 3.1 指标1：算法、3种场景训练、参数规模

当前情况：

- 三个真实场景训练链路已打通。
- 三个真实场景模型参数量都已超过 500 万。
- 训练页已经支持受灾区域录入、应急设备录入、组网算法选择、恢复目标配置和高级参数配置。

当前缺什么：

- 缺少“模型参数总量”页面展示字段。
- 缺少直接面向专家演示的参数规模核验入口。
- 若后续需要提升专家演示直观性，可补充训练结果摘要页和参数统计卡片。

为什么当前测试仍有改进空间：

- 训练页已具备参数配置能力，但参数统计结果仍主要依赖训练结果材料和后台统计，不是全部集中展示在同一界面。
- 当前训练记录详情可看到训练总步数、学习率、折扣因子、Rollout 步长、Checkpoint 和运行目录，但还看不到“模型参数总量”。

建议补齐：

- 在训练详情中增加：
  - 场景名
  - 算法名
  - 参数总量
  - 当前奖励配置
  - 当前高级设置摘要

### 3.2 指标2：组网方案、场景≥5、方式≥4、40Mbps、95%

当前情况：

- 三个真实场景都可生成组网结果。
- 规划产物中存在 `per_user_bandwidth_mbps = 40.0` 和 `target_bandwidth_utilization = 0.95`。
- 但真实场景总数只有 3。
- 前端没有专门展示这两个阈值。

当前缺什么：

- 缺第 4、5 个真实场景。
- 缺组网结果指标卡片。
- 缺“当前已覆盖场景数”和“已支持方式数”自动统计。

为什么当前测试无法完全直观执行：

- 结果页能看奖励和覆盖率，但看不到 40Mbps 和 95% 的理论达标信息。

建议补齐：

- 数据层新增至少 2 个真实场景。
- 后端在组网结果中直接返回：
  - `supported_scene_count`
  - `supported_mode_count`
  - `theoretical_per_user_bandwidth_mbps`
  - `theoretical_bandwidth_utilization`
- 前端测试页增加“理论指标卡片”和“达标状态标签”。

### 3.3 指标3：≥4类极端灾害数据仿真

当前情况：

- 当前只有台风、洪水、地震 3 类真实仿真场景。
- 缺少第 4 类真实场景。
- 前端灾害类型下拉虽然有 `滑坡`，但它不是后端真实场景，也不能完成整套训练/仿真闭环。

当前缺什么：

- 缺暴雨场景或其他第 4 类真实场景。
- 缺与该场景匹配的数据、设备库、奖励配置、训练权重路径。

建议补齐：

- 在 `data/scenarios.json` 中新增第 4 类灾害场景。
- 同步补：
  - `communication_modes`
  - `broadcast_modes`
  - `mode_profiles`
  - `broadcast_profiles`
  - `base_stations`
  - `reward_profiles`
- 确保 `GET /api/scenarios` 能直接返回。

### 3.4 指标4：蜂窝、WiFi、卫星、短波通信方式

当前情况：

- 四类方式在数据层存在。
- 设备页也能通过 `supported_modes` 间接看到。
- 但没有“独立方式开关”和“方式级结果过滤器”。

当前缺什么：

- 缺前端独立选择器。
- 缺测试页结果中的“本次实际使用方式”汇总。
- 缺方式级对比图。
- 缺测试页显式模式选择控件；当前只能通过“添加基站”后显示支持模式与默认激活模式间接观察。

为什么当前测试不够直观：

- 只能从字符串和导出结果推断，而不是点一下“卫星模式”“短波模式”就看到结果。

建议补齐：

- 在 `#/tester` 新增“通信方式过滤区”：
  - 蜂窝
  - WiFi
  - 卫星
  - 短波
- 后端仿真结果增加：
  - `used_comm_modes`
  - `mode_usage_count`
  - `mode_usage_ratio`
- 回放页增加按通信方式高亮。

### 3.5 指标5：直连/中继转发 + 单/组/广播播发

当前情况：

- 当前仓库里有“中继设备”的概念。
- 也有广播覆盖的统计结果。
- 但没有把“直连/中继转发”建模为独立传输方式。
- 也没有把“单播/组播/广播”建模为独立播发模式。

当前缺什么：

- 缺统一的模式枚举。
- 缺前端配置控件。
- 缺后端结果字段。
- 缺回放层的模式标识。
- 缺任意自定义设备导入能力；当前测试页只支持残余基站类型和网格位置接入。

建议补齐：

- 后端新增统一字段：
  - `transport_mode`: `direct` / `relay`
  - `delivery_mode`: `unicast` / `groupcast` / `broadcast`
- 前端新增配置面板：
  - 传输方式选择
  - 播发方式选择
- 结果区新增：
  - 当前传输方式
  - 当前播发方式
  - 模式组合统计
- 回放页节点或链路高亮：
  - 直连链路
  - 中继链路
  - 单播路径
  - 组播范围
  - 广播范围

### 3.6 指标6：强化学习、随机优化控制、策略调度3种逻辑

当前情况：

- 强化学习路径已实现。
- 当前可切换 `PPO / DQN / A3C / MPPO`。
- 但“随机优化控制”没有独立实现。
- “策略调度”也没有独立命名、独立控制器和独立页面。

当前缺什么：

- 缺逻辑类型与算法类型的分层设计。
- 缺“随机优化控制”实现。
- 缺“策略调度”实现。

建议补齐：

- 前端新增“资源配置逻辑类型”一级切换：
  - 强化学习
  - 随机优化控制
  - 策略调度
- 后端新增逻辑执行器：
  - `rl`
  - `random_optimization`
  - `strategy_scheduler`
- 结果区新增三类逻辑对比卡片。

### 3.7 指标7：不少于1500个用户节点接入

当前情况：

- `typhoon_residual` 已满足 `1500` 用户。
- 其他场景低于 1500。

当前缺什么：

- 缺更多大规模场景。
- 缺前端“按用户规模筛选场景”的能力。
- 缺大规模性能展示面板。

建议补齐：

- 至少再补 1 到 2 个 `1500+` 场景。
- 前端新增规模筛选器：
  - `<1200`
  - `1200-1499`
  - `>=1500`
- 结果页新增：
  - 实际用户规模
  - 连接用户数
  - 广播覆盖用户数
  - 渲染耗时
  - 仿真耗时

## 6. 数据与配置补齐建议

### 6.1 场景扩展

- 至少新增 2 个真实灾害场景。
- 优先新增：
  - 暴雨
  - 滑坡或泥石流

### 6.2 大规模样本扩展

- 至少新增 1 个 `1500+` 样本场景。
- 每个新增场景都要补完整的：
  - 通信制式
  - 广播方式
  - 基站设备
  - 奖励配置
  - 时序资源数据

## 7. 可视化与结果展示补齐建议

### 7.1 训练页

- 新增参数总量显示。
- 新增场景训练达标标记。
- 新增报告挂载区。

### 7.2 测试页

- 新增已使用通信方式统计。

## 8. 推荐开发优先级

| 优先级 | 工作项 |
|---|---|
| 高 | 补第4、第5个真实场景 |
| 高 | 补暴雨场景 |
| 高 | 补报告中心和技术进展报告挂载 |
| 高 | 补理论指标卡片 |
| 高 | 补通信方式独立切换和展示 |
| 高 | 补随机优化控制逻辑 |
| 高 | 补策略调度逻辑 |
| 高 | 补直连/中继转发和单/组/广播模式 |
| 中 | 补1500+场景扩展 |
| 中 | 补证据打包导出 |

## 9. 建议验收顺序

1. 先补场景数量和第 4 类灾害场景。
2. 再补理论指标展示和报告中心。
3. 再补通信方式独立切换能力。
4. 再补直连/中继转发与单/组/广播组合模型。
5. 再补随机优化控制和策略调度逻辑。
6. 最后补大规模场景扩展和证据打包导出。

## 10. 补齐后的验收方式

- 补完场景后，按 `#/train` 和 `#/tester` 重新执行场景化测试用例。
- 补完方式与模式后，按 `TC-MODE-*` 和 `TC-CAST-*` 逐项复测。
- 补完逻辑后，按 `TC-LOGIC-*` 逐项复测。
- 补完理论指标展示后，按 `TC-PLAN-05` 和 `TC-PLAN-06` 复测。
- 补完报告中心后，按 `TC-ALG-04` 复测。
