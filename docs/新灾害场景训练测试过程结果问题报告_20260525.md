## 1. 适配范围

本次将训练/测试入口从旧的 `data/scenarios.json` 场景切换到新接入数据集 `data/extreme_disaster_resources/regions.json`。

已完成的代码适配：

| 模块 | 适配内容 |
| --- | --- |
| `data/resource_dataset.py` | 支持读取 `regions.json`，将 3 个灾害场景 × 4 个受灾等级展开为 12 个可训练场景，命名格式为 `{scenario}__{severity}`。 |
| `data/resource_dataset.py` | 从 `deployment_samples.jsonl` 提取真实部署网格作为候选部署点，并基于 `cell_user_count` 生成用户聚集簇。 |
| `data/resource_dataset.py` | 将数据集中的覆盖半径 km 转为训练环境使用的网格半径；暴雨单点经纬度自动扩展为有效地图范围。 |
| `data/resource_dataset.py` | 因 `regions.json` 没有广播指标，临时从卫星、蜂窝、短波/WiFi 链路派生 3 类广播通道：`satellite_broadcast`、`cell_broadcast`、`emergency_radio`。 |
| `envs/multimodal_comm_env.py` | 候选部署点优先使用新数据集真实 `grid_position`，不足时再随机补齐。 |
| `configs/default_config.py` | 默认多模态数据集改为 `data/extreme_disaster_resources/regions.json`，默认训练场景改为 `super_typhoon__level_4_extreme`。 |
| `train.py` / `eval.py` | 增加 `--dataset-path`，训练入口增加 `--artifact-dir`，便于在不覆盖原产物的情况下复现实验。 |

## 6. 发现的问题

| 编号 | 问题 | 影响 | 建议 |
| --- | --- | --- | --- |
| P1 | 接口设计文档中的枚举为 `typhoon/earthquake/rainstorm`、`mild/moderate/severe/catastrophic`，当前后端实际使用 `super_typhoon/destructive_earthquake/extreme_rainstorm`、`level_1_general` 至 `level_4_extreme`。 | 如果前端或调用方按接口文档传参，会出现 422 或 400。 | 统一接口文档与实现，或在 `server/schemas.py` / `server/disaster_import_manager.py` 增加别名映射。 |
| P2 | `DisasterImportManager.create_import()` 中 `unique_user_count` 当前按非离线站点 `cell_user_count` 累加，本次 `super_typhoon/level_4_extreme` 导入返回 533；训练适配从业务会话 `user_id` 推断为 1600。 | 导入概览的“用户数”与训练环境用户规模不一致，验收展示易产生口径冲突。 | 导入侧改为按 `business_users.jsonl.user_id` 去重，或在响应中区分 `unique_user_count` 与 `served_cell_user_count`。 |
| P3 | `regions.json` 只有通信 `mode_metrics`，没有广播 `broadcast_metrics`。 | 当前训练适配使用派生广播指标，能跑通但不属于原始实测广播数据。 | 数据集补充广播时序字段，或明确派生规则并写入数据说明。 |
| P4 | `business_users.jsonl` 没有用户坐标，只有 `deployment_id`。 | 训练用户空间分布只能由站点网格和 `cell_user_count` 派生，不是逐用户真实坐标。 | 若后续要做精确用户级地图和调度，应增加用户网格/经纬度，或正式采用热力图聚合口径。 |
| P5 | 地震场景 `destructive_earthquake` 的业务文件末尾 `user_id` 显示约 600 个用户，而相关设计资料提到 3900 用户。 | 地震场景可能不满足 1200+ 用户节点指标，或统计口径未统一。 | 复核数据生成脚本与用户去重口径，补齐元数据中的场景级真实用户数。 |

## 7. 结论

新灾害数据集已能被训练环境直接读取并展开为 12 个训练/测试场景。本次在 `super_typhoon__level_4_extreme` 上完成了 PPO、DQN、A3C、MPPO、HMARL 全部算法的短训练、checkpoint 生成和策略评估测试，证明训练测试主链路已适配新场景。

当前主要风险集中在接口枚举口径、导入用户数统计口径、广播指标派生和用户空间坐标缺失。建议先统一接口和统计口径，再扩大训练步数做正式收敛实验。
