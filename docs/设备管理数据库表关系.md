# 设备管理数据库表关系

设备管理不再以临时 JSON 作为主要状态源。场景设备状态落到
`data/scenario_devices.db`，由 `server/scenario_device_manager.py` 初始化和维护。

## 关系模型

```text
scenario_registry 1 ── N scenario_grid_cells
scenario_registry 1 ── N scenario_devices
scenario_grid_cells 1 ── N scenario_devices
scenario_registry 1 ── N scenario_device_type_configs
scenario_registry 1 ── N scenario_device_events
```

## 表设计

### scenario_registry

12 个训练/测试场景各一行。

关键字段：

- `scenario_name`: 场景主键，例如 `destructive_earthquake__level_1`
- `display_name`: 展示名称
- `disaster_type`: 灾害类型
- `source_scenario`: 原始灾害目录
- `severity_level`: 灾害等级
- `grid_rows`, `grid_cols`: 网格规模
- `grid_json`: 场景网格边界、标签等原始结构
- `created_at`, `updated_at`: 维护时间

### scenario_grid_cells

每个场景的每个网格块一行。

关键字段：

- `cell_id`: 自增主键
- `scenario_name`: 外键到 `scenario_registry`
- `row_index`, `col_index`: 网格坐标
- `cell_label`: 可选网格标签
- `metadata_json`: 后续可放地理边界、受灾等级、人口统计等块级属性

唯一约束：

- `(scenario_name, row_index, col_index)`

### scenario_devices

每台可管理设备一行，既支持基站设备，也支持用户设备。

关键字段：

- `device_uid`: 设备实例主键
- `scenario_name`: 所属场景
- `device_kind`: `base_station` 或 `user_device`
- `row_index`, `col_index`: 所在网格
- `type_key`: 设备类型。基站为 `base_station` profile key，用户设备可为终端类型
- `mode`: 通信模式
- `status`: `active`、`degraded`、`offline`、`planned` 等状态
- `device_name`, `device_category`: 实例级展示/分类
- `source_deployment_id`: 灾害数据源部署 ID
- `source_station_type`, `source_station_label`: 原始基站类型信息
- `coverage_radius`, `coverage_radius_km`: 覆盖能力
- `max_throughput`, `downlink_bandwidth_mbps`, `uplink_bandwidth_mbps`: 吞吐/带宽
- `max_users`, `cell_user_count`: 容量和源数据用户数
- `tx_power_watt`, `battery_duration_h`: 发射功率和续航
- `demand_mbps`, `connected`, `broadcast_served`: 用户设备侧字段
- `override_fields_json`: 单设备覆盖过的参数字段
- `extra_json`: 兼容新增字段

外键：

- `scenario_name -> scenario_registry.scenario_name`
- `(scenario_name, row_index, col_index) -> scenario_grid_cells`

### scenario_device_type_configs

场景内按设备类型配置默认参数。单设备参数覆盖优先级高于类型配置。

关键字段：

- `scenario_name`: 所属场景
- `device_kind`: `base_station` 或 `user_device`
- `type_key`: 设备类型
- `config_json`: 类型级参数配置

主键：

- `(scenario_name, device_kind, type_key)`

### scenario_device_events

设备 CRUD 和块数量调整的追踪记录。

关键字段：

- `event_id`: 自增主键
- `scenario_name`: 所属场景
- `operation`: 操作类型，例如 `add_device`、`update_device`、`delete_device`
- `device_uid`: 相关设备，可为空
- `device_kind`, `type_key`, `row_index`, `col_index`: 操作上下文
- `device_count`, `active_count`, `degraded_count`, `offline_count`: 操作后的统计快照
- `payload_json`: 操作详情
- `created_at`: 操作时间

## CRUD 映射

- 查看场景设备现状：读取 `scenario_registry`、`scenario_grid_cells`、`scenario_devices`、`scenario_device_type_configs`
- 新增设备：向 `scenario_devices` 插入实例，并写入 `scenario_device_events`
- 修改单设备：更新 `scenario_devices` 的实例参数和状态，并写入事件
- 删除设备：从 `scenario_devices` 删除实例，并写入事件
- 修改块内基站数量：按 `(scenario_name,row_index,col_index,type_key,mode,status)` 重建该块设备实例
- 修改类型参数：更新 `scenario_device_type_configs`
- 训练/测试导入场景：读取 `scenario_devices` 的最新设备快照
