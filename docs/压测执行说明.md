# RescueNet-RL 压测执行说明

本文档说明 RescueNet-RL 在本机执行 1200 节点并发能力压测的方法，包含 JMeter 图形化界面执行和命令行执行两种方式。

## 1. 前置条件

项目目录：

```powershell
D:\Projects\RescueNet-RL
```

JMeter 目录：

```powershell
D:\Projects\RescueNet-RL\jmeter\apache-jmeter-5.6.3
```

当前保留的 1200 节点 GUI 压测脚本：

```powershell
D:\Projects\RescueNet-RL\jmeter\rescuenet_1200_nodes_paced_gui.jmx
```

命令行压测脚本：

[scripts/run_jmeter_6_endpoints_1200.sh](D:/Projects/RescueNet-RL/scripts/run_jmeter_6_endpoints_1200.sh)

```powershell
D:\Projects\RescueNet-RL\scripts\run_jmeter_6_endpoints_1200.sh
```

GUI 默认结果输出目录：

```powershell
D:\Projects\RescueNet-RL\artifacts\load_tests\jmeter_gui\rescuenet_1200_nodes_paced
```

## 2. 启动后端服务

压测前需要先启动本地 API 服务。

```powershell
cd D:\Projects\RescueNet-RL
.\.venv\Scripts\python.exe -m uvicorn server.api:app --host 127.0.0.1 --port 8000 --backlog 8192 --timeout-keep-alive 30
```

另开一个 PowerShell 窗口检查服务是否正常：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
```

期望返回：

```json
{"status":"ok"}
```

## 3. JMeter GUI 压测执行方法

启动 JMeter 图形化界面：

```powershell
cd D:\Projects\RescueNet-RL
$env:HEAP='-Xms1g -Xmx4g -XX:+UseG1GC'
& 'D:\Projects\RescueNet-RL\jmeter\apache-jmeter-5.6.3\bin\jmeter.bat' -t 'D:\Projects\RescueNet-RL\jmeter\rescuenet_1200_nodes_paced_gui.jmx'
```

进入 JMeter 后：

1. 确认左侧测试计划已加载。
2. 点击工具栏绿色 Start 按钮，或按 `Ctrl+R`。
3. 等待测试自动结束。
4. 查看左侧 `Summary Report`。

当前脚本默认配置：

```text
users = 1200
ramp = 60
timer_delay = 10000 ms
loops = 1
host = 127.0.0.1
port = 8000
```

测试含 6 个接口，每个接口 1200 次请求，总请求数 7200：

```text
GET /api/health
GET /api/scenarios
GET /api/devices
GET /api/replay/sessions?limit=5
GET /api/mahimahi/status
GET /api/ns3/status
```

## 4. JMeter 命令行压测执行方法

命令行压测使用项目内置脚本：

[scripts/run_jmeter_6_endpoints_1200.sh](D:/Projects/RescueNet-RL/scripts/run_jmeter_6_endpoints_1200.sh)

```powershell
D:\Projects\RescueNet-RL\scripts\run_jmeter_6_endpoints_1200.sh
```

该脚本会顺序执行 6 个独立 JMeter 压测任务，每个接口默认使用 1200 个虚拟用户。脚本会自动生成每个接口的 `results.jtl`、`jmeter.log`、HTML 报告，并汇总生成 `summary.json` 和 `report.md`。

在 Windows 本机执行 `.sh` 脚本时，建议使用 Git Bash、WSL Bash 或其他 Bash 环境，并确保以下命令可用：

```bash
jmeter
curl
python3
```

当前机器已在 Git Bash 的 `~/.bashrc` 中配置好 JMeter、Java 和 Python3，正常打开 Git Bash 后可直接执行脚本。如果在新环境中 JMeter 未加入 PATH，需要先把 JMeter 的 `bin` 目录加入当前 Bash 会话 PATH：

```bash
export PATH="/d/Projects/RescueNet-RL/jmeter/apache-jmeter-5.6.3/bin:$PATH"
```

默认执行：

```bash
cd /d/Projects/RescueNet-RL
scripts/run_jmeter_6_endpoints_1200.sh
```

推荐显式指定本机目标和输出目录：

```bash
cd /d/Projects/RescueNet-RL

export HEAP="-Xms1g -Xmx6g -XX:+UseG1GC -XX:-HeapDumpOnOutOfMemoryError"

scripts/run_jmeter_6_endpoints_1200.sh \
  --users 1200 \
  --ramp 60 \
  --loops 1 \
  --host 127.0.0.1 \
  --port 8000 \
  --protocol http \
  --timeout 30000 \
  --out-dir artifacts/load_tests/jmeter/separate_1200_latest
```

PowerShell 中可以通过 Git Bash 调用：

```powershell
cd D:\Projects\RescueNet-RL

& 'D:\Program files\Git\bin\bash.exe' -lc 'cd /d/Projects/RescueNet-RL && export HEAP="-Xms1g -Xmx6g -XX:+UseG1GC -XX:-HeapDumpOnOutOfMemoryError" && scripts/run_jmeter_6_endpoints_1200.sh --users 1200 --ramp 60 --loops 1 --host 127.0.0.1 --port 8000 --protocol http --timeout 30000 --out-dir artifacts/load_tests/jmeter/separate_1200_latest'
```

命令行输出目录：

```powershell
D:\Projects\RescueNet-RL\artifacts\load_tests\jmeter\separate_1200_latest
```

核心产物：

```powershell
D:\Projects\RescueNet-RL\artifacts\load_tests\jmeter\separate_1200_latest\summary.json
D:\Projects\RescueNet-RL\artifacts\load_tests\jmeter\separate_1200_latest\report.md
```

## 5. 结果判定方法

GUI 压测通过条件：

```text

success=true = 7200
success=false = 0
responseCode=200 = 7200
最大 allThreads/grpThreads = 1200
```

GUI 结果可以用 PowerShell 统计：

```powershell
$jtl = 'D:\Projects\RescueNet-RL\artifacts\load_tests\jmeter_gui\rescuenet_1200_nodes_paced\results.jtl'
$data = Import-Csv $jtl

$data.Count
$data | Group-Object success | Select-Object Name,Count
$data | Group-Object responseCode | Select-Object Name,Count
$data | Group-Object label | Sort-Object Name | Select-Object Name,Count
$data | ForEach-Object {[int]$_.allThreads} | Measure-Object -Maximum
```

## 6. 常见问题

如果出现 `Connection refused`，通常是本机瞬时 TCP 建连压力过大，先确认后端服务仍然健康：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
```

如果后端未启动或端口被占用，检查 8000 端口：

```powershell
Get-NetTCPConnection -LocalPort 8000 -ErrorAction SilentlyContinue
```

如果 JMeter GUI 卡顿，确认已设置 4GB heap：

```powershell
$env:HEAP='-Xms1g -Xmx4g -XX:+UseG1GC'
```

如果需要重新执行，建议先删除旧的 `results.jtl`，避免把历史结果和新结果混在一起。
