# 仿真系统界面修改大纲

基于 [仿真系统界面优化讨论.md](/root/Projects/RescueNet-RL/仿真系统界面优化讨论.md) 的反馈，当前系统的主要问题不是单点功能缺失，而是整体观感、信息架构、演示链路和可配置能力不足。本文档给出后续界面与交互改造的大纲。

## 1. 改造目标

1. 将当前系统从“功能堆叠页面”升级为“完整的仿真平台界面”。
2. 突出平台感、科技感、应急通信场景感，弱化当前偏灰暗、块状、机械拼接的界面风格。
3. 让前端能够体现后端工作量和系统复杂度，而不是看起来像简单原型。
4. 优化演示路径，避免训练慢、仿真慢、数据未生成导致页面空白或异常。

## 2. 一级信息架构重组

建议将系统重构为三大一级模块：

1. 算法模拟
2. 场景模拟
3. 虚拟设备模拟

现有功能建议归类如下：

1. 算法训练、算法测试、参数配置、训练日志，归入“算法模拟”。
2. ns-3 回放、场景演化、节点链路展示，归入“场景模拟”。
3. 设备展示、设备说明、参数说明、设备能力介绍，归入“虚拟设备模拟”。
4. Mahimahi 网络能力分析可作为“场景模拟”或“算法模拟”的子模块。

## 3. 首页改造

1. 首页改成展示型封面页，不再直接堆训练、测试、回放面板。
2. 首页应突出系统正式名称、副标题、平台定位和三个一级模块入口。
3. 首页视觉应更偏“应急通信数字孪生平台”风格，具备场景感和科技感。
4. 首页建议加入大幅背景视觉、动态装饰层、场景化说明，而不是现有的简单功能卡片排列。

## 4. 系统名称与文案统一

1. 统一首页标题、模块标题、页面副标题。
2. 替换当前不规范、不统一的系统命名。
3. 所有模块说明改为正式、学术化、平台化表达。
4. 错误提示、状态提示、流程说明改为更明确的中文文案。

## 5. 整体视觉风格改造

1. 重做整体配色，避免当前偏阴沉、偏暗、缺少层次的效果。
2. 优化页面留白、层级关系、字体搭配和控件尺寸。
3. 弱化大块矩形拼接感，提升模块边界和内容组织的自然度。
4. 减少遮挡主内容的悬浮组件。
5. 建立统一的图标、按钮、标签、状态色、图表风格体系。

## 6. 算法模拟页改造

### 6.1 页面目标

1. 从“简单训练入口”升级为“高可配置算法实验台”。
2. 让用户明显感知到系统支持大量输入、自定义和实验控制。

### 6.2 输入配置改造

1. 增加可调参数项数量。
2. 按类别组织输入项：
   - 场景参数
   - 算法参数
   - 奖励函数参数
   - 训练资源参数
   - 仿真规模参数
   - 日志与输出参数
3. 支持默认模板、快速填充、参数折叠与高级设置。

### 6.3 输出区改造

1. 输出区分为：
   - 训练实时日志
   - 核心指标看板
   - 曲线图表
   - 模型状态/输出产物
2. 强化训练过程中的反馈，不要只显示简略事件。

## 7. 训练日志与控制台改造

1. 现有“实时事件”升级为控制台风格日志区域。
2. 控制台支持自动滚动、时间戳、日志等级、状态标签。
3. 尽量接入真实训练迭代日志，而不只是抽象状态。
4. 日志区尺寸应更大，便于展示长过程输出。
5. 提供预生成演示日志能力，避免现场演示时日志为空。

## 8. 场景模拟页与回放页改造

### 8.1 布局改造

1. 场景图不要只占局部区域，应成为页面中心主体。
2. 场景回放建议进入独立页面或整页工作台。
3. 地图、节点、链路、状态演化应占据主要视觉空间。
4. 控制栏、图例、状态摘要应围绕主场景布置，而不是压缩主画面。

### 8.2 回放流程说明改造

1. 不再把“回放流程”长期固定放在左侧。
2. 改为弹窗、引导层、提示条或可关闭说明卡片。
3. 首次进入页面时再展示操作说明。

### 8.3 演示链路改造

1. 提供预生成的回放数据，避免必须现场长时间运行仿真。
2. 提供小规模场景演示模式，确保演示稳定。
3. 对“数据尚未生成完毕”提供明确的状态反馈。

## 9. 节点与链路可视化改造

1. 用更清晰的图标替代当前仅靠颜色区分的节点样式。
2. 不同设备类型使用不同图标或贴图：
   - 用户终端
   - 宏基站
   - 背负式基站
   - 中继设备
   - 临时设备/车载设备
3. 节点点击后应支持查看详情。
4. 链路样式应能体现链路类型和状态，不只靠颜色变化。
5. 若当前图形信息量不足，可删去低价值图表，避免占位置但缺少解释力。

## 10. 虚拟设备模拟页改造

1. 设备展示不应只是简单卡片堆叠。
2. 每个设备应支持详情页或详情弹窗。
3. 设备介绍内容建议包括：
   - 设备实物图
   - 功能简介
   - 应用场景
   - 核心参数
   - 与奖励设计或调度策略的关系
4. 使用更贴近真实设备的素材，替换抽象占位图。

## 11. 说明信息与帮助方式改造

1. 把常驻左侧说明改为轻量级交互式帮助。
2. 使用 tooltip、drawer、modal、引导步骤等方式承载说明信息。
3. 将“系统介绍”和“当前操作说明”分层处理。
4. 不要让帮助说明长期占用主工作区。

## 12. 稳定性与演示能力改造

1. 补充预置训练结果、预置回放日志、预置场景数据。
2. 对耗时任务增加明确状态机：
   - 未开始
   - 初始化中
   - 运行中
   - 已完成
   - 失败
3. 对失败场景提供可读错误说明。
4. 对长时间任务提供后台执行和日志查看能力。

## 13. 工程实施顺序

建议按以下阶段推进：

### 第一阶段：信息架构与首页

1. 统一名称和文案。
2. 重构首页。
3. 拆分一级导航为三个模块。

### 第二阶段：算法模拟页

1. 扩充输入配置区。
2. 重做训练日志控制台。
3. 强化输出结果展示。

### 第三阶段：场景模拟页

1. 重做回放页面布局。
2. 整合全屏主画布。
3. 完成节点图标和详情交互。

### 第四阶段：虚拟设备模拟页

1. 增加设备详情介绍。
2. 接入实物图和说明内容。
3. 重做设备展示方式。

### 第五阶段：演示链路与稳定性

1. 预置演示数据。
2. 增加演示模式和快速模式。
3. 完善错误提示、状态提示和帮助引导。

## 14. 最终效果目标

1. 系统第一眼应体现“平台感”和“完成度”。
2. 前端应能展示后端算法、仿真、回放等工作的复杂性。
3. 演示时即使实时训练或实时仿真较慢，也始终有可展示内容。
4. 用户能够清楚理解三大模块：算法模拟、场景模拟、虚拟设备模拟。
5. 整体界面应更适合正式汇报、论文展示和答辩演示。
