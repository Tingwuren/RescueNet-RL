# 仿真系统技术名词建议

## 1. 编制说明

本文档结合当前 RescueNet-RL 仿真系统的代码实现、组网架构和相关设计文档，整理可用于项目汇报、技术指标表、验收材料和产品说明书的技术名词。

表格按照示例中的五列结构组织：

> 技术模块｜技术方向/机制｜技术子方向或待解决问题｜具体技术名词｜技术实现说明

其中，技术名词尽量采用“技术路线可描述、系统实现有依据、适合正式材料”的表述。

## 2. 技术名词建议表

| 技术模块 | 技术方向/机制 | 技术子方向或待解决问题 | 具体技术名词 | 技术实现说明 |
|---|---|---|---|---|
| 算法及核心模块 | 分层资源统筹机制 | 全局—区域—节点的任务分解 | 分层多智能体强化学习（HMARL） | 采用 L1 全局决策、L2 区域协调、L3 节点执行三级架构。 |
| 算法及核心模块 | 多智能体协同机制 | 全局策略与局部执行的一致性 | 集中训练、分布式执行（CTDE） | 全局环境集中维护状态，各层智能体依据全局或局部信息执行决策。 |
| 算法及核心模块 | 策略优化机制 | 策略更新幅度过大导致训练不稳定 | 近端策略优化（PPO） | 使用裁剪概率比目标函数，抑制策略更新幅度。 |
| 算法及核心模块 | 策略优化机制 | 长期回报估计方差较大 | 广义优势估计（GAE） | 使用折扣因子和 GAE 参数计算优势函数，降低策略梯度方差。 |
| 算法及核心模块 | 多场景策略机制 | 不同灾害场景的策略适配 | 多头近端策略优化（MPPO） | 共享特征提取网络，通过多策略头适配不同场景或奖励目标。 |
| 算法及核心模块 | 多目标调度机制 | 覆盖、广播、吞吐和成本难以兼顾 | 多目标奖励塑形 | 联合考虑通信覆盖、广播覆盖、吞吐、资源成本和约束惩罚。 |
| 算法及核心模块 | 可行性约束机制 | 动作超出设备库存或站点条件 | 动作掩码（Action Masking） | 屏蔽超出设备预算、无效站点或不满足当前状态的动作。 |
| 算法及核心模块 | 策略增强机制 | 强化学习早期探索效率不足 | 规则引导动作先验 | 根据区域优先级、站点评分、制式评分和广播评分辅助动作选择。 |
| 算法及核心模块 | 全局资源配置机制 | 区域需求与设备库存的匹配 | 全局资源配额矩阵 | L1 层输出区域—设备类型配额矩阵，并传递库存和优先级硬约束。 |
| 算法及核心模块 | 区域资源协调机制 | 区域间资源不均衡 | 跨区域资源迁移 | L2 层依据区域需求、剩余资源和优先级进行资源协调。 |
| 算法及核心模块 | 异构通信融合机制 | 多种通信制式的链路选择 | 多制式异构链路融合 | 统一协调 5G、卫星、WiFi6、短波及灾后残余网络链路。 |
| 算法及核心模块 | 融合业务调度机制 | 广播业务与通信业务相互竞争资源 | 广播通信联合优化 | 将应急广播覆盖和双向通信覆盖纳入同一资源配置目标。 |
| 算法及核心模块 | 网络恢复机制 | 残余网络条件差异较大 | 残余网络感知自适应组网 | 根据是否存在灾后残余基站，切换残余网络和无残余网络组网模式。 |
| 场景与环境模块 | 灾情场景生成机制 | 多灾种、多损毁程度场景配置 | 参数化灾害场景建模 | 支持台风、暴雨、洪水、地震等极端灾害场景配置。 |
| 场景与环境模块 | 状态演化机制 | 灾害、用户和链路随时间变化 | 确定性—随机混合状态演化 | 通过恢复趋势叠加参数化随机扰动模拟灾害演化。 |
| 场景与环境模块 | 用户需求建模机制 | 不同用户群体通信需求不同 | 多类型用户需求建模 | 区分受灾群众、救援人员和指挥人员的数量、优先级及带宽需求。 |
| 场景与环境模块 | 环境不确定性模拟 | 需求突增、容量下降和设备故障 | 通信链路压力测试 | 支持需求增长、容量下降、覆盖半径变化和设备可用率下降等压力参数。 |
| 资源配置与组网模块 | 设备部署机制 | 候选站点与应急设备匹配 | 基于网格的应急设备部署 | 将灾区划分为部署网格，在候选站点配置基站、网关、中继和 UAV。 |
| 资源配置与组网模块 | 拓扑生成机制 | 区域内和跨区域链路构建 | 点位感知拓扑构建 | 根据节点区域、网格位置、节点角色和距离生成链路。 |
| 资源配置与组网模块 | 广播承载机制 | 广播业务的多跳传播 | 多跳广播树构建 | 以指挥中心为根节点，组织公众告警、救援通信和现场回传路径。 |
| 资源配置与组网模块 | 组网执行机制 | 从规划结果到可执行部署方案 | 分阶段组网部署 | 按资源规划、设备部署、链路恢复和方案导出等阶段执行。 |
| 仿真与验证模块 | 链路容量仿真机制 | 带宽和发送速率的时变仿真 | Trace 驱动网络仿真 | 通过 Mahimahi trace 回放链路容量和发送速率变化。 |
| 仿真与验证模块 | 原生网络仿真机制 | 真实协议栈和链路行为验证 | ns-3 场景回放 | 接入 ns-3 运行结果、链路 trace 和场景回放数据。 |
| 仿真与验证模块 | 链路评估机制 | 多类链路指标统一展示 | 三类关键链路聚合评估 | 聚合用户接入、残余网络和灾区回程链路的吞吐、利用率和成功率。 |
| 仿真与验证模块 | 恢复过程仿真机制 | 测试、回放和链路指标统一关联 | 灾害—受损—恢复状态回放 | 通过 `replay_id` 关联策略测试、场景回放和链路指标。 |
| 仿真与验证模块 | 实时仿真机制 | 训练测试过程实时反馈 | 服务端事件流（SSE） | 通过 `text/event-stream` 实时输出训练、测试和链路仿真过程。 |
| 系统支撑模块 | 实验数据管理机制 | 模型、指标和日志可追溯 | 回放产物闭环管理 | 管理元数据、逐帧数据、链路指标、日志、报告和场景导出文件。 |

## 3. 优先推荐使用的技术名词

以下名词与当前系统实现和项目技术路线的匹配度较高，适合优先放入正式技术指标表或成果材料：

1. 分层多智能体强化学习（HMARL）
2. 集中训练、分布式执行（CTDE）
3. 多制式异构链路融合
4. 广播通信联合优化
5. 残余网络感知自适应组网
6. 全局资源配额矩阵
7. 规则引导动作先验
8. 参数化灾害场景建模
9. 点位感知拓扑构建
10. 分阶段组网部署
11. Trace 驱动网络仿真
12. 三类关键链路聚合评估
13. 灾害—受损—恢复状态回放
14. 回放产物闭环管理
15. 服务端事件流实时仿真
