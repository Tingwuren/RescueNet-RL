# 系统输入输出规范

> 日期：2026-07-09
> 目标：说明 RescueNet-RL 的输入来自哪里、训练/测试/回放输出保存在哪里、前端列表从哪里读取，以及历史记录按什么时间排序。

## 1. 总原则

前端不直接读取磁盘目录。前端页面通过后端 API 读取整理后的列表、详情和回放帧。

磁盘目录是归档位置，API 返回结果是前端展示口径。浏览器 `localStorage` 只用于临时状态和兼容旧记录，不作为验收或长期归档依据。

```text
数据集 / 设备状态 / 训练参数 / 测试请求
  -> 后端 API
    -> 训练、测试或回放生成
      -> artifacts、data、ns-3.46.1 等目录落盘
        -> 前端再通过 API 读取历史和详情
```

## 2. 输入来源

| 输入类型 | 权威位置 | 说明 |
| --- | --- | --- |
| 极端灾害数据集 | `data/extreme_disaster_resources/` | 当前主要灾害场景来源，入口为 `regions.json` |
| 旧版场景数据 | `data/scenarios.json` | 极端灾害数据集不可用时的回退数据 |
| 专用设备库 | `data/dedicated_devices.db` | 设备管理页面新增、编辑、启停的设备 |
| 场景设备状态 | `data/scenario_devices.db` | 各场景基站、网格、状态和参数覆盖 |
| Mahimahi trace | `data/traces/` | 链路仿真输入 |
| ns-3 trace | `ns-3.46.1/trace.json` | ns-3 原生仿真导出的待导入 trace |

灾害数据导入接口 `POST /api/disaster-imports` 当前生成的是后端内存会话。服务重启后导入会话会丢失；长期依据仍是原始数据集和后续测试/回放产物。

## 3. 训练输入输出

训练入口：

```http
POST /api/train
GET /api/train/{run_id}/stream
```

主要输入包括 `scenario_name`、`algorithm`、`env_type`、`total_timesteps`、`reward_mode`、`evaluation_protocol`、`custom_base_stations` 等。

每次训练输出目录：

```text
artifacts/runs/<yyyyMMdd_HHmmss>_<algorithm>_<scenario_name>_<run_id>/
```

示例：

```text
artifacts/runs/20260709_104159_hmarl_extreme_rainstorm__level_4_eb58e225b2904f52aead7aaffa418ec3/
```

典型文件：

| 文件 | 说明 |
| --- | --- |
| `policy_meta.json` | 模型元信息，包含算法、场景、权重路径、运行 ID、创建时间 |
| `training_metrics.json` | 训练奖励、覆盖率、广播率、评估记录和配置快照 |
| `<algorithm>_policy.pt` | 模型权重 |
| `training_coverage_curve.png` | 训练曲线图片 |
| `broadcast_architecture_<scenario>.json` | 多模态组网架构导出 |

最新训练副本还会保存在：

```text
artifacts/policy_meta.json
artifacts/training_metrics.json
artifacts/training_coverage_curve.png
```

前端训练历史读取：

```http
GET /api/train/artifacts
```

排序规则：按 `updated_at` 倒序。`updated_at` 来自 `policy_meta.json` 和 `training_metrics.json` 的最新修改时间。不要用文件系统默认枚举顺序判断训练先后。

## 4. 策略测试输入输出

测试入口：

```http
POST /api/simulate
POST /api/simulate/stream
```

主要输入包括 `scenario_name`、`checkpoint_path`、`algorithm`、`episodes`、`custom_devices`、`custom_base_stations`、`dataset_import_ids` 等。

测试响应中的关键输出：

| 字段 | 说明 |
| --- | --- |
| `avg_reward` | 平均奖励 |
| `avg_final_coverage` | 平均最终覆盖率 |
| `reports` | episode 详细报告 |
| `deployment_plan` | 部署方案 |
| `scene_export` | 场景导出路径和内容 |
| `replay_session_id` | 本次测试生成的回放 ID |
| `replay_session_path` | 回放会话落盘目录 |

测试场景导出保存到：

```text
artifacts/scene_exports/<yyyyMMdd_HHmmss>_<scenario>_episode_<n>_<suffix>/
```

典型文件：

| 文件 | 说明 |
| --- | --- |
| `metadata.json` | 测试导出元数据，包含 `created_at`、`scenario_name`、`scenario_label` 和各文件路径 |
| `disaster_scene.json` | 受灾初始场景 |
| `deployment_scene.json` | 部署后场景 |
| `deployment_plan.json` | 部署方案 |

测试输出列表读取：

```http
GET /api/test/outputs
```

排序规则：按 `metadata.json.created_at` 倒序。

说明：前端“测试记录”会优先合并 `/api/test/outputs` 返回的后端落盘记录，再用浏览器 `localStorage` 补充奖励、覆盖率等本地指标。因此 `artifacts/scene_exports` 是测试场景导出的权威归档，`localStorage` 不是权威来源。

## 5. 场景回放输入输出

策略测试完成后，后端会把测试报告转换成可逐帧播放的回放会话。

回放会话保存到：

```text
artifacts/replay_sessions/<replay_id>/
```

示例：

```text
artifacts/replay_sessions/rpl_20260709_171926_97d96c/
```

典型文件：

| 文件 | 说明 |
| --- | --- |
| `metadata.json` | 回放列表和详情使用的元数据 |
| `request.json` | 创建回放时的测试请求 |
| `report.json` | 测试响应完整报告 |
| `frames.jsonl` | 逐帧回放数据 |
| `link_metrics.jsonl` | 每帧链路指标 |
| `nodes_full.jsonl` | 完整节点清单 |
| `replay.log` | 回放日志 |

前端可选择的回放列表读取：

```http
GET /api/replay/sessions
```

回放详情和逐帧读取：

```http
GET /api/replay/sessions/{replay_id}
GET /api/replay/sessions/{replay_id}/frames
GET /api/replay/sessions/{replay_id}/frames/{frame_index}
GET /api/replay/sessions/{replay_id}/logs
GET /api/replay/sessions/{replay_id}/link-metrics
GET /api/replay/sessions/{replay_id}/download?type=...
```

排序规则：

1. 优先按 `metadata.json.created_at` 倒序。
2. 如果 `created_at` 缺失或无效，则解析目录名 `rpl_<yyyyMMdd_HHmmss>_<suffix>`。
3. 如果目录名也无法解析，则使用 `metadata.json` 文件修改时间。

前端回放页面还会在收到 API 返回后按 `created_at` 再排序一次，防止缓存或异常返回顺序影响展示。

## 6. ns-3 与 Mahimahi 输出

Mahimahi 输入 trace 位于：

```text
data/traces/
```

ns-3 原生 trace 位于：

```text
ns-3.46.1/trace.json
```

ns-3 导入后的实验历史保存到：

```text
ns-3.46.1/simulation_history.db
```

常用读取接口：

```http
GET /api/experiments
GET /api/exp/{exp_id}/charts
GET /api/exp/{exp_id}/frame/{frame_idx}
```

ns-3 实验列表按数据库自增 ID 倒序展示。

## 7. 场景中文名规范

前端展示和测试导出 metadata 中统一使用以下中文业务名称：

| 机器场景名 | 展示名称 |
| --- | --- |
| `flood_no_residual`、`extreme_rainstorm__level_*`、`water_disaster__level_*` | 洪水孤岛通信恢复 |
| `earthquake_residual`、`destructive_earthquake__level_*` | 地震灾后断链恢复 |
| `typhoon_residual`、`super_typhoon__level_*` | 台风灾后残余网络 |

`scenario_name` 保留机器标识，用于训练、测试和文件关联；`scenario_label` 用于页面展示和人工查看。

## 8. 权威来源总表

| 业务 | 权威存储位置 | 前端读取接口 | 排序依据 |
| --- | --- | --- | --- |
| 训练历史 | `artifacts/runs/` | `/api/train/artifacts` | `updated_at` 倒序 |
| 训练详情 | `artifacts/runs/<run>/` | `/api/train/artifacts/detail` | 指定目录 |
| 最新训练副本 | `artifacts/` | `/api/train/latest-artifact` | 单条最新副本 |
| 测试场景导出 | `artifacts/scene_exports/` | `/api/test/outputs` | `metadata.created_at` 倒序 |
| 回放会话 | `artifacts/replay_sessions/` | `/api/replay/sessions` | `metadata.created_at` 倒序，目录名兜底 |
| 专用设备 | `data/dedicated_devices.db` | `/api/devices` | 数据库记录 |
| 场景设备状态 | `data/scenario_devices.db` | `/api/scenarios/{scenario}/device-state` | 数据库记录 |
| 灾害导入会话 | 后端内存 | `/api/disaster-imports` | 非长期归档 |
| Mahimahi trace | `data/traces/` | `/api/mahimahi/traces` | 文件列表 |
| ns-3 实验 | `ns-3.46.1/simulation_history.db` | `/api/experiments` | 数据库 ID 倒序 |
| 前端本地缓存 | 浏览器 `localStorage` | 前端本地读取 | 非权威 |

## 9. 常见不一致说明

前端列表和磁盘目录看起来不一致时，按下面口径判断：

1. 前端训练历史来自 `/api/train/artifacts`，不是 `Get-ChildItem artifacts/runs` 的自然顺序。
2. 前端测试记录优先来自 `/api/test/outputs`，本地 `prototype-tester-history` 只补充指标。
3. 前端回放列表来自 `/api/replay/sessions`，对应磁盘目录是 `artifacts/replay_sessions/`。
4. 旧版平铺的 `artifacts/scene_exports/*_scene.json` 文件只作为历史兼容，新测试输出应使用时间戳子目录。
5. 人工查看磁盘目录时，应按 `metadata.json.created_at` 或目录名前缀排序，不能依赖文件系统默认顺序。

## 10. 验收口径

验收或联调时建议这样表述：

1. 系统输入包括灾害数据集、设备库、场景设备状态、训练参数、模型权重和测试请求。
2. 训练输出保存在 `artifacts/runs/`，前端训练历史从 `/api/train/artifacts` 读取。
3. 测试输出保存在 `artifacts/scene_exports/`，前端测试记录从 `/api/test/outputs` 读取。
4. 回放输出保存在 `artifacts/replay_sessions/`，前端回放列表从 `/api/replay/sessions` 读取。
5. 回放验收以 `metadata.json`、`frames.jsonl`、`nodes_full.jsonl`、`link_metrics.jsonl` 和 `replay.log` 为准。
6. 灾害导入会话是内存态，不作为长期归档依据。
