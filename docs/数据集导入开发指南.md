  总体思路
  不要让浏览器直接读取 3.8G 解压数据，也不要在前端解析大量 jsonl。前端只做“导入/选择/展示”，后端负责扫描
  data/extreme_disaster_resources，生成轻量索引和统计摘要。

  当前后端训练只读 data/scenarios.json，新数据集是目录结构：

  灾害场景 -> 灾害等级 -> 通信类型 -> 基站类型 -> resource_profile / deployment_samples / business_users

  所以不能直接替换现有 ResourceDataset，需要加一个适配层。

  后端方案

  1. 新增 data/extreme_resource_dataset.py
      - 读取 data/extreme_disaster_resources/metadata.json
      - 扫描所有 resource_profile.json
      - 生成轻量索引，不直接加载所有 business_users.jsonl
      - 统计：
          - 灾害场景数：3
          - 灾害等级数：4
          - 通信类型：5G 700MHz、Satellite Ka、WiFi6、Shortwave HF
          - 资源 profile 数：约 120
          - 文件数：363
          - 数据体量：3.8G
  2. 新增 API：
      - GET /api/datasets/extreme/status
          - 返回数据集是否存在、路径、大小、文件数、更新时间。
      - POST /api/datasets/extreme/import
          - 注册该数据集到当前系统，返回导入成功状态。
      - GET /api/datasets/extreme/summary
          - 返回 metadata 摘要、灾害场景、等级、通信类型、基站类型统计。
      - GET /api/datasets/extreme/resources?scenario=&severity=&communication=
          - 返回筛选后的资源 profile 列表。
      - GET /api/datasets/extreme/resources/{resource_id}
          - 返回单个资源详情，包括带宽、成功率、覆盖半径、站点状态统计等。
  3. 可选：生成缓存文件
      - data/extreme_disaster_resources/index.cache.json
      - 避免每次打开训练页都递归扫描 3.8G 目录。

  前端训练界面方案
  在“模型训练”页的原型界面中，建议加一个新的折叠段：

  数据集导入

  位置建议放在：
  场景录入 后、导入组网算法 前。

  内容布局：

  - 左侧：数据集状态
      - 数据集名称：Measured Disaster Communication Resource Dataset
      - 类型：field_measurement_fusion
      - 路径：data/extreme_disaster_resources
      - 状态：未导入 / 已导入 / 索引生成中
      - 按钮：导入扩展数据集
  - 中间：概览指标卡
      - 灾害场景：3
      - 灾害等级：4
      - 通信类型：4
      - 资源剖面：120
      - 文件数：363
      - 数据大小：3.8G
  - 下方：筛选和表格
      - 灾害场景：超强暴雨 / 特大台风 / 破坏性地震
      - 灾害等级：一般 / 中等 / 严重 / 特别严重
      - 通信类型：5G 700MHz / Satellite Ka / WiFi6 / Shortwave HF
      - 基站类型：宏站、背负微站、车载卫星终端、便携热点等
      - 表格展示：
          - 资源 ID
          - 灾害场景
          - 灾害等级
          - 通信类型
          - 基站类型
          - 下行带宽均值
          - 上行带宽均值
          - 连接成功率
          - 覆盖半径
          - 在线/离线站点数
  - 右侧详情面板
      - 选中某一行后展示 resource_profile.json 的关键字段：
          - 业务吞吐
          - 覆盖半径
          - 发射功率
          - 连接尝试数/成功数/失败数
          - 部署样本数
          - active/degraded/offline 比例
          - damaged station ratio

  训练接入方案
  第一期只展示，不改变训练逻辑。

  第二期再做训练接入：

  - 在训练 payload 里增加：
      - dataset_source: "default" | "extreme"
      - extreme_resource_filters
  - 后端把选中的 profile 转换成现有环境需要的：
      - base_station_profiles
      - mode_profiles
      - user_clusters
      - candidate_sites
      - reward_profiles
  - 这样可以逐步替换或增强 data/scenarios.json，不会一次性破坏现有训练流程。

  建议优先实现
  先做第一期：

  4. 暂时不让它影响训练启动参数。
