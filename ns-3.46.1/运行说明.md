# 应急通信数字孪生平台运行说明

本文档对应当前仓库内的融合版本，目录基准为：

```bash
/home/tingwuren/Projects/RescueNet-RL
```

与旧版说明不同，当前推荐把 `RescueNet-RL` 主后端、`ns-3` 回放后端和前端开发服务分开运行，避免端口冲突。

## 1. 关键目录与端口

- `server.api:app`：RescueNet 主后端，默认 `8000`
- `ns-3.46.1/server_pro.py`：ns-3 实验导入与回放 API，建议 `8001`
- `frontend`：Vue + Vite 前端，开发模式通常为 `5173`
- `ns-3.46.1/index.html`：ns-3 原生静态回放页，建议 `8080`

## 2. 依赖准备

先在仓库根目录执行：

```bash
bash scripts/update_pytorch_env.sh
```

该脚本会在 `pytorch` Conda 环境中安装：

- 根目录 `requirements.txt`
- `ns-3.46.1/requirements.txt`
- `sumolib`

如果只想手动安装 `ns-3` 侧依赖，也可以执行：

```bash
conda run -n pytorch pip install -r ns-3.46.1/requirements.txt
conda run -n pytorch pip install sumolib>=1.19.0
```

## 3. 推荐启动顺序

推荐使用 3 个终端；如果需要打开 ns-3 原生 HTML 回放页，再额外开第 4 个终端。

### 终端 A：编译并运行仿真

```bash
cd /home/tingwuren/Projects/RescueNet-RL/ns-3.46.1
rm -f trace.json simulation_history.db
./ns3 build
./ns3 run scratch/disaster-pro
```

说明：

- `trace.json` 是仿真输出的逐帧数据。
- `simulation_history.db` 是 `server_pro.py` 导入后的实验库。
- 如果修改了 `scratch/disaster-pro.cc`，建议重新执行一次 `./ns3 build`。

可选参数示例：

```bash
./ns3 run "scratch/disaster-pro --simTime=300 --disasterTime=150"
```

### 终端 B：启动 ns-3 回放 API

```bash
cd /home/tingwuren/Projects/RescueNet-RL/ns-3.46.1
uvicorn server_pro:app --host 0.0.0.0 --port 8001
```

说明：

- `server_pro.py` 启动时会检查 `trace.json`，并自动导入到 `simulation_history.db`。
- 之后它会持续监控新的 `trace.json` 文件，并导入为新的实验记录。
- 这里显式使用 `8001`，是为了避开 `RescueNet` 主后端占用的 `8000`。

健康检查：

```bash
curl http://localhost:8001/api/health
```

### 终端 C：启动 RescueNet 主后端和前端

先启动主后端：

```bash
cd /home/tingwuren/Projects/RescueNet-RL
uvicorn server.api:app --reload --port 8000
```

再启动前端：

```bash
cd /home/tingwuren/Projects/RescueNet-RL/frontend
npm install
npm run dev
```

健康检查：

```bash
curl http://localhost:8000/api/health
```

### 终端 D：可选，启动 ns-3 原生静态回放页

```bash
cd /home/tingwuren/Projects/RescueNet-RL/ns-3.46.1
python3 -m http.server 8080
```

访问：

```text
http://localhost:8080/index.html
```

## 4. 前端环境变量

在 `frontend/.env.local` 中建议配置：

```bash
VITE_API_BASE=http://localhost:8000/api
VITE_NS3_API_BASE=http://localhost:8001/api
VITE_NS3_WEB_BASE=http://localhost:8080/index.html
```

如果不配置，前端会根据当前浏览器主机名自动回退到这三个默认地址。

## 5. 回放中心的数据来源

当前回放中心会同时汇总两类数据：

1. `RescueNet` 训练/测试生成的本地回放
2. `ns-3` 导入数据库后的真实实验回放

具体行为如下：

- 训练中心完成一次训练后，会基于最新模型产物自动生成一条“训练回放”。
- 测试中心完成一次仿真评估后，会自动保存一条“测试回放”。
- 回放中心会从浏览器本地存储读取这些 RL 回放，也会从 `http://localhost:8001/api/experiments` 拉取 ns-3 实验列表。
- 选中 ns-3 实验后，前端会按帧请求 `/api/exp/{exp_id}/frame/{frame_idx}` 并绘制节点和链路。

## 6. 常见问题

### 1) 为什么不直接运行 `python3 server_pro.py`？

可以运行，但该脚本默认监听 `8000`，会与 `RescueNet` 主后端冲突。当前仓库推荐改用：

```bash
uvicorn server_pro:app --host 0.0.0.0 --port 8001
```

### 2) 回放中心看不到 ns-3 实验怎么办？

按顺序检查：

- `trace.json` 是否已由终端 A 成功生成
- `uvicorn server_pro:app --port 8001` 是否正常运行
- `http://localhost:8001/api/experiments` 是否能返回实验列表
- 前端 `.env.local` 中的 `VITE_NS3_API_BASE` 是否正确

### 3) 回放中心只能看到 RL 测试结果，看不到训练结果怎么办？

训练回放依赖主后端提供的最新训练产物元数据。需要确认：

- `artifacts/policy_meta.json` 已生成
- `artifacts/training_metrics.json` 存在且可读
- `http://localhost:8000/api/train/latest-artifact` 返回 200
