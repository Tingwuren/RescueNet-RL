## 四、测试设计总原则

本次不是沿用旧版测试大纲的写法，而是要 **重新设计全部测试用例**。

设计原则如下：

### 1. 所有测试用例必须“直观”

每个测试用例都必须满足以下要求：

- 测试人员能在前端找到入口
- 能通过点击、选择、输入、提交等动作触发
- 前端必须有明确响应
- 测试人员能直接观察结果
- 能截图或录屏作为证据

如果某能力目前不能做到“前端点击即可观察”，不能假装已经具备，必须：

- 在测试大纲中标注当前限制
- 在后续开发指南中给出补齐方案

### 2. 测试用例必须按指标重新拆解

不要照抄旧版测试编号和旧版测试项。
要根据结项指标重新拆解成一组更直观、更容易演示的测试用例。

### 3. 测试用例拆分要细，但不能空泛

所谓“细”，是指要把一个大指标拆成多个可单独点击和观察的用例；
不是写大段空话，也不是堆无意义的过程描述。

### 4. 每个测试用例必须体现“前端动作 -> 系统响应 -> 可见结果”

每个测试用例都必须写清：

- 从哪个页面进入
- 点击哪个按钮 / 选择哪个选项 / 输入什么参数
- 前端出现什么状态变化
- 后端执行什么任务
- 页面上最终展示什么结果
- 如何判定通过

### 5. 所有未实现功能必须被识别出来

如果当前项目缺少：

- 前端操作入口
- 对应后端接口
- 对应计算逻辑
- 对应可视化展示
- 对应日志/结果页/报告页

则不能跳过，必须记录到 `后续开发指南.md`。
